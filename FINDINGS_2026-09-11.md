# Overnight findings — 2026-09-11

Three results, in increasing order of importance. Everything below is
read-only work on branch `fix/goalkeeper-training-gap`; **nothing has been
merged to `main` and no logged prediction was touched.**

---

## 1. A real bug: goalkeepers were never trained on

The four-season archive labels goalkeepers **`GK`**. The live FPL API labels
them **`GKP`**. [`model.py:53`](model.py#L53) filters training data with
`isin(["GKP","DEF","MID","FWD"])`, so every goalkeeper row was silently dropped.

| | |
|---|---:|
| Goalkeeper rows in `history` | **12,500** |
| Share of the archive | **11.0%** |
| Goalkeepers reaching training | **0** |
| `is_gkp` values seen in training | `{0}` — **a constant** |
| Goalkeeper predictions logged for GW4 | **71** |

Two consequences, neither of which raised an error:

- `is_gkp` — the single feature that tells the model a player is a keeper — was
  dead weight. It never once took the value 1.
- Prediction rows come from the live API, which says `GKP`, so keepers sailed
  through the filter and **were predicted by a model that had seen none**.

Nothing crashed. Nothing warned. The numbers looked entirely reasonable.

## 2. Fixing it changes almost nothing measurable

Trained two models differing **only** in whether goalkeeper rows were in the
training set, scored on identical test rows and identical candidate pools.

> The first attempt at this got it wrong and is superseded. It scored the
> champion on 26,320 rows and the challenger on 29,747 — different test sets —
> so the apparent MAE improvement 0.9538 → 0.9123 was mostly composition:
> goalkeeper rows have MAE ~0.58, far below outfield, so adding them drags the
> mean down regardless of skill. The ranking comparison had the mirror flaw:
> top-20 is chosen from the candidate pool, and the champion's pool contained
> no keepers at all.

**Outfield players** (identical rows, identical pool):

| training set | MAE | high-return MAE | top-20 pts |
|---|---:|---:|---:|
| outfield only (current) | 0.9538 | 5.3048 | **4.393** |
| + goalkeepers | 0.9559 | 5.2826 | **4.291** |

Paired bootstrap over 38 gameweeks: **−0.103**, 95% CI **[−0.258, +0.043]**,
P(better) = 0.08. **Contains zero — noise.**

**Goalkeepers themselves** — and this is not the clean win it should be:

| model | MAE | high-return MAE | mean bias |
|---|---:|---:|---:|
| never trained on a keeper | **0.5261** | 4.8356 | −0.1593 |
| trained on keepers | 0.5770 | **4.3501** | **−0.0139** |

Overall keeper MAE gets **worse**; high-return MAE gets **10% better**; the
systematic bias is almost entirely removed. The untrained model was
*accidentally* accurate by being uniformly pessimistic, which scores well when
most keeper returns are near zero. Top-5 keeper ranking: 3.521 → 3.432, CI
[−0.326, +0.153] — noise.

**Verdict: a correctness fix with no demonstrable accuracy benefit.** Worth
merging because predicting 71 players per gameweek from zero training data is
indefensible on its own terms, not because it makes the engine better.

## 3. The finding that actually matters: the model cannot resolve small gaps

Fixing the bug moved individual GW4 predictions a long way — Palmer −1.385,
Isak −1.316, B.Fernandes +0.807 — while aggregate accuracy did not move at all.
That combination demanded a control, so the same comparison was run against a
change that should mean **nothing**: the random seed.

GW4, all 656 players. `mean|Δ| >2` restricts to players actually pickable.

| comparison | mean \|Δ\| | mean \|Δ\| >2 | max \|Δ\| | spearman |
|---|---:|---:|---:|---:|
| goalkeeper fix (seed fixed at 42) | 0.079 | **0.184** | 1.385 | 0.9779 |
| **seed only, 42 → 7 (control)** | 0.075 | **0.177** | 1.560 | 0.9972 |
| **seed only, 42 → 99 (control)** | 0.065 | **0.161** | 1.064 | 0.9970 |
| outfield only — goalkeeper fix | 0.073 | 0.168 | 1.385 | 0.9957 |
| outfield only — seed only | 0.079 | 0.181 | 1.560 | 0.9972 |

**Changing nothing but the random seed moves a pickable player's predicted
score by 0.169 points on average, and by as much as 1.56.**

The goalkeeper fix moves it by 0.184 — indistinguishable. On outfield players
the fix moves predictions *less* than reseeding does.

### What follows from this

**Any gap smaller than roughly 0.17 expected points is noise.**

The GW4 captaincy decision came down to **B.Fernandes 6.05 vs Palmer 5.97 — a
gap of 0.08**, less than half the noise floor. The engine did not have a
preference between those two players. It reported one anyway, to two decimal
places, and that false precision is what made it look like a disagreement worth
resolving.

This vindicates the decision to overrule it on fixture difficulty. Not because
the overlay is cleverer than the model, but because **the model was mute on
that question and did not say so.**

It also retires a scare from earlier tonight: the fixed model appears to flip
the captaincy to B.Fernandes by 2.27 points. That flip sits inside the same
noise — the largest seed-only swing measured was 1.56 on a single player. It is
not a signal.

### Recommended change to how the engine reports

The engine should refuse to express a preference it does not have. Concretely:

- `compare.py` and `recommend.py` should treat gaps below ~0.2 xPts as **tied**
  and say so, rather than ranking to two decimals.
- Captaincy output should read *"B.Fernandes and Palmer are tied within model
  noise — decide on fixtures"* instead of picking one.
- The noise floor should be **measured per retrain**, not hardcoded, since it
  will change as the feature set and data volume change.

That is a real product change driven by measurement, and it makes the system
more honest rather than more accurate — which, for a decision support tool, is
the more valuable direction.

## Practical answer for GW4

**The Horníček → Pickford transfer stands.** Re-running the live prediction
path with the bug fixed:

| keeper | broken model | fixed model |
|---|---:|---:|
| **Pickford** | 3.380 | **3.909** |
| Horníček | 3.087 | 3.138 |

Broken model preferred Pickford by +0.292; fixed model prefers Pickford by
**+0.771** — a gap comfortably above the noise floor, and the only decision all
gameweek that clears it. Across all 71 keepers the mean prediction rose 0.121
and rank correlation was 0.909, so the ordering did move — but not this call.

would overwrite the GW4 predictions logged in advance — destroying both the
honest record and the engine-vs-gut comparison. **Merge after GW4 is scored.**
